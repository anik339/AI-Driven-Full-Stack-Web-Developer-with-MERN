Task 17 · GitHub collaboration

Tag a Release and Write Release Notes

Use semantic version tags to mark a stable project release.

Problem 17 of 50git tag · semantic versioning · GitHub Releases
Read full task guide ↗Module 09 guide ↗

Problem statement

Create an annotated v1.0.0 tag for a stable practice project, push the tag, and prepare release notes for GitHub.

What to practise

  • Understand the concept before writing code.
  • Use clear names and small, focused steps.
  • Test normal behavior and at least one edge case.
  • Explain the solution without relying on comments alone.

Stretch challenge

Explain when a change should increment MAJOR, MINOR, or PATCH in semantic versioning.

Expected behavior

The annotated tag points to the intended commit and appears on GitHub after it is pushed.

Focus: git tag · semantic versioning · GitHub Releases

PowerShell / Git command reference

These are Git commands for a terminal. The browser cannot execute them.

# Confirm the working tree is clean before tagging.
git status --short
# Create an annotated release tag with a useful message.
git tag -a v1.0.0 -m "Release 1.0.0: first stable learning project"
# Inspect the tag and the commit it references.
git show v1.0.0
# Publish the tag to the remote repository.
git push origin v1.0.0
# On GitHub, open Releases → Draft a new release and select v1.0.0.
# Summarize added features, fixes, known limitations, and upgrade notes.

Output / practice checklist

Git commands are shown for manual execution in PowerShell. They are not executed by this webpage.
