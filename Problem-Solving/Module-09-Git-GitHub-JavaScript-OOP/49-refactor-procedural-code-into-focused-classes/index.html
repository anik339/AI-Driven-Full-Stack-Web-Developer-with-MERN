Problem statement

Refactor a function that validates a user, stores it, and formats a message into Validator, Repository, and Service responsibilities.

What to practise

  • Understand the concept before writing code.
  • Use clear names and small, focused steps.
  • Test normal behavior and at least one edge case.
  • Explain the solution without relying on comments alone.

Stretch challenge

Add an EmailValidator collaborator and inject it into UserService without making the service know validation details.

Expected behavior

The user name is normalized and stored; each class has one clear responsibility.

Focus: refactoring · single responsibility · cohesion

Commented JavaScript solution (study after attempting)

Try the problem yourself before opening this reference solution.

function runSolution() {
  class UserValidator {
    validate(input) {
      const name = String(input.name ?? "").trim();
      if (name.length < 2) throw new Error("Name is required");
      return { ...input, name };
    }
  }
  class UserRepository {
    users = [];
    save(user) { this.users.push(user); return user; }
  }
  class UserService {
    constructor(validator, repository) {
      this.validator = validator;
      this.repository = repository;
    }
    register(input) {
      const validUser = this.validator.validate(input);
      return this.repository.save(validUser);
    }
  }

  const repository = new UserRepository();
  const service = new UserService(new UserValidator(), repository);
  const user = service.register({ id: 1, name: "  Anik  " });
  console.log(`Registered ${user.name}; total users: ${repository.users.length}`);
}

Output / practice checklist

The user name is normalized and stored; each class has one clear responsibility.
