Foundation

How the Internet Works

IP Addresses · DNS · The request-response cycle

When you type example.com into a browser, a remarkable chain of events unfolds in milliseconds. Your computer doesn't know where that site lives — it must ask.

01

IP Address

Every device has a unique numerical address. IPv4 looks like 192.168.1.1; IPv6 like 2001:0db8::1. It's the postal address of the internet.

02

DNS

The DNS translates human-readable domains (google.com) into machine IPs. A distributed, hierarchical directory — the internet's phone book.

03

HTTP Request

Once the IP is known, your browser sends an HTTP request. The server responds with HTML, CSS, and JS. The browser parses and renders.

"The internet is a network of networks — each device a node, each connection a thread in an ever-expanding web."

— Web Fundamentals, Module 1

Semantic HTML5

Semantic Structure

Tags that give meaning to content — not just visual style

Semantic HTML5 tags communicate the purpose of content to browsers, assistive technologies, and search engines. This very page uses all of the structural landmarks shown below. 

<!DOCTYPE html>        — Document type declaration (required, not a tag)
<html lang="en">      — Root element with language attribute

<head>                — Metadata container (invisible to user)
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width">
  <title>Page Title</title>

<body>                — All visible content lives here
  <header>            — Masthead or section intro
  <nav>               — Navigation block (use aria-label for multiples)
  <main>             — Primary content — only ONE per page
  <article>           — Self-contained, re-usable content unit
  <section>           — Thematic grouping (needs a heading)
  <aside>             — Tangentially related / sidebar content
  <footer>            — Footer for page or section
  <figure>            — Self-contained media with optional caption
  <figcaption>        — Caption for figure
  <address>           — Contact information
  <time datetime="">  — Machine-readable date/time

Links & Anchors

The <a> tag — the connective tissue of the web

The anchor tag is the fundamental primitive of hypertext. Its href, target, rel, and download attributes unlock different linking behaviours.

Anchor / Jump ↑ Section Jump ↓ Email Link Tel Link External ↗ Download 
<a href="https://...">Regular link</a>
<a href="#section-id">Jump to anchor</a>
<a href="mailto:you@example.com">Email</a>
<a href="tel:+880...">Phone call</a>
<a href="file.pdf" download>Force download</a>
<a href="..." target="_blank" rel="noopener noreferrer">New tab</a>

<details> / <summary> — FAQ

What is the DOM?
The Document Object Model is a programming interface for web documents. It represents the page as a tree so JavaScript can modify structure, style, and content dynamically.
What is the CSS Box Model?
Every element is a rectangle: content → padding → border → margin. Understanding this model is foundational to laying out any web page.
What is event bubbling?
Events fire on the target element and propagate upward through ancestors. A click on a button also fires on its parent div, then body, then document.
What is semantic HTML?
Using HTML tags that describe the meaning of content (not just appearance). <nav> communicates navigation; <article> communicates an independent piece of content.

Scripting & Canvas

script · noscript · canvas — bringing HTML to life with JavaScript

The <script> tag embeds or links JavaScript. The <canvas> tag provides a pixel-based 2D drawing surface accessible via the Canvas API. Draw on the canvas below: 

<!-- Inline script -->
<script>
  console.log('Hello, world!');
</script>

<!-- External script (defer = non-blocking) -->
<script src="app.js" defer></script>

<!-- ES module -->
<script type="module" src="main.js"></script>

<!-- Fallback when JS is disabled -->
<noscript>
  <p>This page requires JavaScript.</p>
</noscript>
Special Purpose

Special Purpose Tags

meta · link · base · template · slot · noscript · data · ruby

<meta>

Document metadata — charset, viewport, description, author, Open Graph, theme-color. Lives in <head>. Void element.

<link>

Links external resources: stylesheets, icons, manifest, preconnect hints. Void element — no closing tag needed.

<template>

Inert HTML not rendered until cloned via JavaScript. Used in Web Components and repeated UI patterns. See the live demo below.

<slot>

A placeholder inside a Web Component's shadow DOM where consumer-provided (light DOM) content is projected.

<noscript>

Fallback content when JavaScript is disabled. Critical for progressive enhancement. Can appear in <head> or <body>.

<base>

Sets the base URL for all relative links and the default target for links. One per page; must be in <head>.

<data>

Links machine-readable content to human-readable text via the value attribute. E.g. <data value="398">Mini</data>.

<ruby> / <rt>

Ruby annotations for East Asian typography — shows pronunciation or meaning above/beside characters. Critical for CJK accessibility.

<wbr>

Word Break Opportunity — hints where long strings may wrap. Useful for URLs, variable names, or long compound words.

data-*

Custom data attributes on any element. Accessed via element.dataset.myKey. Store private data for JavaScript without abusing class names.

Advanced

Advanced Web Page Structure

ARIA · Accessibility · Performance · Progressive Enhancement · SEO

ARIA & Roles

Add role, aria-label, aria-labelledby, aria-hidden, and aria-live to bridge the gap between visual design and screen readers. This page uses them throughout.

Loading Performance

loading="lazy", decoding="async", <link rel="preconnect">, fetchpriority="high", and defer/async on scripts reduce LCP and TTI.

Progressive Enhancement

Start with semantic HTML that works without CSS or JS. Layer in styles, then behaviour. Every user — regardless of device or network — gets a functional experience.

SEO & Meta

Open Graph, Twitter Cards, JSON-LD structured data, canonical URLs, and a sensible heading hierarchy help search engines parse content and social platforms generate rich previews. 

<!-- Core meta in <head> -->
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<meta name="description" content="…">
<meta name="theme-color" content="#FAF7F0">

<!-- Open Graph -->
<meta property="og:title"       content="Page Title">
<meta property="og:description" content="…">
<meta property="og:image"       content="https://…/og.jpg">
<meta property="og:type"        content="website">

<!-- ARIA landmarks already set by semantic tags -->
<header role="banner">
<nav    aria-label="Main navigation">
<main   id="main-content">
<footer role="contentinfo">

<!-- Skip link (keyboard / screen reader UX) -->
<a href="#main-content" class="skip-link">Skip to main content</a>
