# Git and Version Control Fundamentals

Understand version control, repositories, snapshots, distributed Git, and the working-tree/staging/commit model.

     ## Learn
 - Why version control matters in a software project.
 - The difference between Git (a version-control tool) and GitHub (a hosting and collaboration platform).
 - Working directory, staging area, local repository, and remote repository.
 - How commits form a history of snapshots.

 ## Practise
 1. Explain in your own words why copying folders such as `project-final-final-2` is not a reliable version-control strategy.
 2. Draw the four areas: working directory → staging area → local repository → remote repository.
 3. Identify which area changes after editing a file, running `git add`, `git commit`, and `git push`.

 ## Challenge
 Write a five-sentence explanation of how Git helps a developer safely experiment without losing earlier work.

 ## Expected result
 You can explain the difference between Git and GitHub and describe where a change lives before and after a commit.


## Study method
1. Read the lesson completely.
2. Run each command in a separate disposable practice repository where instructed.
3. Predict the result before pressing Enter.
4. Inspect the result with `git status`, `git log`, or the GitHub interface.
5. Complete the challenge without copying a solution.
