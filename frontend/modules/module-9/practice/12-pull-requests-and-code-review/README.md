# Pull Requests and Code Review

Propose changes from a feature branch, review the diff, respond to feedback, and merge responsibly.

     ## Standard workflow
 1. Update your local `main` branch.
 2. Create a feature branch.
 3. Make small commits.
 4. Push the branch to GitHub.
 5. Open a Pull Request into `main`.
 6. Describe the problem, solution, and testing performed.
 7. Review the Files changed tab.
 8. Address comments and push follow-up commits.
 9. Merge using the repository's agreed strategy.
 10. Delete the merged feature branch.

 ## Practise
 Open a pull request in your practice repository. Use a checklist:
 - [ ] The change has one clear purpose.
 - [ ] The page works at desktop and mobile widths.
 - [ ] No console errors are present.
 - [ ] No secrets or generated files are included.
 - [ ] The README explains any setup changes.

 ## Challenge
 Review your own PR as if you were a teammate. Identify one maintainability improvement and make the change before merging.


## Study method
1. Read the lesson completely.
2. Run each command in a separate disposable practice repository where instructed.
3. Predict the result before pressing Enter.
4. Inspect the result with `git status`, `git log`, or the GitHub interface.
5. Complete the challenge without copying a solution.
