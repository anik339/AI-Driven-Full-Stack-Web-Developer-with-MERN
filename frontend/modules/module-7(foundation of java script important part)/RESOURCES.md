# Module 07 — JavaScript DOM and Events

> Select and update page elements, create interface content, and respond to user actions.

## Why this resource library exists
This module is about browser-side JavaScript. Use the DOM and event references when a selector, property, event, or browser behaviour is unclear.

## Start here — primary resource
- [MDN — Dynamic Scripting with JavaScript](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting) — A guided module for making web pages interactive, including DOM scripting and browser-side JavaScript concepts.

## Additional trusted resources
- [MDN — Document Object Model (DOM)](https://developer.mozilla.org/en-US/docs/Web/API/Document_Object_Model) — Understand the DOM tree and how JavaScript and browser APIs represent and update documents. *(Web API guide)*
- [JavaScript.info — Document](https://javascript.info/document) — Study DOM tree navigation, searching, element properties, attributes, styles, and document updates. *(In-depth tutorial)*
- [JavaScript.info — Introduction to Events](https://javascript.info/events) — Learn event handling, bubbling, capturing, delegation, and browser default actions. *(In-depth tutorial)*
- [MDN — DOM Events](https://developer.mozilla.org/en-US/docs/Web/API/Document_Object_Model/Events) — Look up event types, event objects, and supported event properties. *(Official reference)*

## Topics to revisit
- querySelector and selecting elements
- textContent, attributes, classList and styles
- createElement, append and remove
- Mouse, keyboard, form events, event object and delegation

## Recommended study method
Run each local lesson with Live Server. Inspect the element in DevTools, change one line, and observe the result. When an event behaves unexpectedly, check the event reference and inspect the event object in the console.

1. Open the matching lesson in this module and read the existing comments first.
2. Search for the exact concept in the recommended documentation.
3. Compare the documentation example with the local code; do not copy it blindly.
4. Change one thing, run the page or project, and inspect the browser console.
5. Write a short explanation in your own words so you can understand it again months later.
