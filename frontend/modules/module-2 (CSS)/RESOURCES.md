# Module 02 — CSS Fundamentals

> Style interfaces with maintainable CSS, layout systems, and responsive rules.

## Why this resource library exists
Use these references to revisit selectors, cascade, box model, typography, Flexbox, Grid, positioning, responsive layouts, and CSS debugging.

## Start here — primary resource
- [MDN — CSS styling basics](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Styling_basics) — A structured course covering CSS syntax, selectors, the cascade, inheritance, values, and fundamental styling techniques.

## Additional trusted resources
- [MDN — CSS Layout](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout) — Learn normal flow, positioning, Flexbox, Grid, and modern layout techniques. *(Official guided course)*
- [web.dev — Learn CSS](https://web.dev/learn/css/) — A deeper course on the box model, selectors, cascade, specificity, inheritance, sizing, layout, and more. *(Guided course)*
- [MDN — CSS Reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference) — Look up CSS properties, selectors, at-rules, values, and syntax details. *(Official reference)*
- [W3C — CSS Validator](https://jigsaw.w3.org/css-validator/) — Use it as a diagnostic tool for stylesheet syntax. Its default validation profile may not represent every modern CSS feature, so investigate warnings with the current MDN reference rather than treating every warning as a definite error. *(Validation tool)*

## Topics to revisit
- Selectors, specificity, cascade and inheritance
- Box model, sizing, typography, colors and units
- Flexbox, Grid, positioning and normal flow
- Media queries, responsive layout and debugging

## Recommended study method
Read MDN CSS styling basics first, then use the CSS Layout course for Flexbox, Grid, and positioning. Keep the MDN CSS Reference open when checking a property. Validate stylesheets after larger edits.

1. Open the matching lesson in this module and read the existing comments first.
2. Search for the exact concept in the recommended documentation.
3. Compare the documentation example with the local code; do not copy it blindly.
4. Change one thing, run the page or project, and inspect the browser console.
5. Write a short explanation in your own words so you can understand it again months later.
