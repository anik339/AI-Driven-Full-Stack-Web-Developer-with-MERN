AI + Responsive Design + GitHub

A complete small-task workflow that keeps the developer responsible for the result.

From task to reviewed change

  1. Plan: create an issue such as "Fix card overflow at 360px" with a clear acceptance criterion.
  2. Inspect: reproduce the issue in browser DevTools before asking AI for help.
  3. Prompt: share only the relevant code and ask for the smallest explainable fix.
  4. Implement: apply the change on a feature branch, not directly on main.
  5. Verify: test mobile, tablet and desktop, keyboard focus, images and links.
  6. Review: inspect the diff, open a pull request and ask a teammate to review.
  7. Merge: resolve feedback and merge only after the team checks are satisfied.

Prevent horizontal overflow on mobile

Acceptance criteria: no accidental page-level horizontal scrolling at 320px; cards remain readable; desktop layout remains unchanged.

feature/fix-mobile-overflow

Commit and pull request

git switch main
git pull
git switch -c feature/fix-mobile-overflow

# Make and test the change
git add path/to/changed-file.html
git commit -m "Fix mobile card overflow"
git push -u origin feature/fix-mobile-overflow

Open a pull request on GitHub and include the problem, the fix, the viewport sizes tested and any AI assistance used under your team's policy.

Definition of done

  • The change solves the issue without unrelated edits.
  • Responsive and accessibility checks are complete.
  • AI suggestions were reviewed and understood.
  • The branch is pushed and the pull request has a clear summary.
  • No secrets or private data were committed.
