Testing, Accessibility and Performance

A responsive page is not complete until it is usable, readable and tested.

Responsive test plan

Viewport What to inspect Expected result
320-390px Navigation, text, buttons No accidental horizontal page scroll
640-900px Cards, forms, spacing Columns appear when content fits
1024px+ Max width, long lines Content stays readable, not stretched

Accessibility basics

  • Use semantic landmarks and a sensible heading order.
  • Give informative images meaningful alt text; use empty alt for decorative images.
  • Connect every form label to its input with matching for and id .
  • Keep keyboard focus visible and all controls reachable without a mouse.
  • Use sufficient text contrast and do not communicate meaning with color alone.
  • Use descriptive link text rather than repeated "click here" labels.

Performance basics

  • Resize and compress images to a suitable size.
  • Use loading="lazy" for below-the-fold images when appropriate.
  • Set image dimensions to reduce layout shifts.
  • Avoid loading libraries that the page does not need.
  • For production, compile Tailwind with the official build workflow rather than relying on the browser CDN.

Browser DevTools checklist

Open device emulation, inspect the computed styles, check console errors, test keyboard navigation, throttle the network when useful, and compare the rendered page with the expected design. Use automated accessibility tools as helpers, not as a substitute for manual testing.
