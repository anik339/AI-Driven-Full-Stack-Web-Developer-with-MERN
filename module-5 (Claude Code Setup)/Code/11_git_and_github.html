LESSON 11 / MODULE 05

Git & GitHub: Branch-based Workflow

Learn the difference between local changes, commits, branches, remote pushes and pull requests.

GitBranchesPull Requests
PRACTICE SECTION

Inspect and commit

These commands assume Git is installed and a repository is already initialized.

CODE EXAMPLE

git status
git diff
git add .
git commit -m "Refine mobile portfolio layout"
git status

Remember: Review changes before git add. Do not add secrets or generated credentials.

PRACTICE SECTION

Make a feature branch

Create a separate line of work instead of editing main directly.

CODE EXAMPLE

git switch main
git pull --ff-only
git switch -c feature/mobile-navigation
# Edit, test and review files, then:
git add .
git commit -m "Improve mobile navigation"
git push -u origin feature/mobile-navigation
PRACTICE SECTION

Pull request and merge

Open a pull request on GitHub from feature/mobile-navigation into main; request review, run checks, and merge if approved.

CODE EXAMPLE

# After your PR is merged on GitHub:
git switch main
git pull --ff-only
git branch -d feature/mobile-navigation

Remember: Never use git push --force to override shared work unless you understand the consequences.

Practice task: Try the example, then change one thing and reload the browser.
