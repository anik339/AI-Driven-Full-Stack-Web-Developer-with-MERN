LESSON 10 / MODULE 05

Claude Code: Prompting and Safe Editing

Use Claude Code to inspect first, change a small part second, and verify diffs and output before saving a commit.

PromptsReviewHuman-in-the-loop
PRACTICE SECTION

Inspect before editing

Ask for a code explanation first. This keeps you in control of what will change.

CODE EXAMPLE

Read my project structure. Explain how index.html and style.css work.
Do not modify any files. List the main accessibility and responsive issues.
PRACTICE SECTION

Make a bounded request

Specify the exact file, device sizes, expected behavior and constraints.

CODE EXAMPLE

Edit only Project/01_developer_portfolio/index.html and style.css.
Improve the mobile navigation and spacing for screens from 320px to 768px.
Keep the existing content and use HTML/CSS/Tailwind only.
Do not add JavaScript or external libraries.
Show a summary of the changes and any remaining issues.
PRACTICE SECTION

Ask for a verification plan

Review and test the output yourself; do not trust an AI assertion of success.

CODE EXAMPLE

Review the change for broken links, semantics and focus styles.
Show which files changed and suggest manual tests at 375px, 768px and 1280px.
Do not commit or push anything.
PRACTICE SECTION

Safety with AI tools

Check file diffs, dependencies and any commands before approving them.

ReviewCheck proposed edits.
TestUse browser and DevTools.
CommitSave a verified change.

Remember: Never allow an assistant to commit secrets or run destructive commands without careful review.

Practice task: Try the example, then change one thing and reload the browser.
